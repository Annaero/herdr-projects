# What was checked on herdr 0.9.3

| Fact | Result |
|---|---|
| Plugin event hooks fire on `pane.agent_status_changed` | yes; the event carries pane id, workspace id, status, agent |
| Popup panes; `HERDR_PLUGIN_CONTEXT_JSON` in a popup | yes; no pane id, but workspace, focused pane and its folder, worktree's repo root |
| `agent focus` from inside a popup holds after it closes | yes |
| A popup pane while another tab shows | it belongs to the tab it was opened over (`tab_id` in `HERDR_PLUGIN_CONTEXT_JSON`): herdr hides it when another tab or space is focused, its program keeps running, and it shows again when that tab does. It lies over every pane of that tab, zoomed or not. While it exists, shown or hidden, `plugin pane open` of any plugin's popup answers `ui_busy: a popup pane is already open`. So the board is not a popup |
| A plugin pane opened with `--placement tab` | a new tab in the focused space holding one ordinary pane: its program gets `HERDR_PANE_ID`, `HERDR_TAB_ID` and `HERDR_PLUGIN_ID`, and `HERDR_PLUGIN_CONTEXT_JSON` still names the pane you came from. The answer carries `plugin_pane.pane` (pane, tab, space). It stays when you go elsewhere, other plugins' popups open beside it, `tab rename` names it, and its tab closes when the program ends. `plugin pane focus <pane>` from another space did not move the client there; `workspace focus` then `tab focus` does |
| Giving one pane the keyboard by its id | no command does it (`pane focus` only goes to a neighbour, `workspace focus` and `tab focus` leave it on whichever pane of the tab had it). `pane zoom <id> --on` focuses that pane, also when another pane of the tab was zoomed, and `--off` after it leaves the focus there: the board key uses that to come back to a board that shares its tab with an agent |
| A second viewer on a pane's terminal (`herdr terminal attach`) | it sets the terminal's size; herdr then shows a cut-out of it from the top left. `pane layout` still gives the size herdr shows, so the board draws inside that and says what holds it; `terminal session control --takeover`, left at once, disconnects the other viewer and herdr sizes the terminal to the pane again: the board does it by itself (setting `ownTerminal`). Nothing else gives the size back while the viewer is attached (a client resize, zoom, `control` without `--takeover`). Not in the popup: it has no pane id |
| `agent start`; `state_change_seq`, `completion_seq` in `agent get` | yes; `completion_seq` appears after the first finished turn |
| When `agent start` says "ready" (seen 2026-10-12, claude 2.1.296, codex 0.160.0, pi 1.1.0) | once the program is the pane's foreground process, about 3.5 s after the command is typed, whatever is on the screen. A program held to 8% of a processor had drawn nothing by then: Claude drew its screen 13 to 17 s after the start, pi 19 s; Codex had drawn |
| What `agent prompt` types (seen by a program that logs its input) | the text as one bracketed paste, then a lone enter 300 ms later. `pane run` sends both in one write; `pane send-text` sends the text bare |
| A prompt typed into Claude before it has drawn its screen | the text is kept and shows in its box, the enter is lost: status stays `idle` and `state_change_seq` does not move, for as long as nobody presses enter (60 s watched). `agent send-keys <pane> enter` then starts it. Typed after the screen was drawn, on the same starved program, the same prompt went through on its own enter; herdr showed `working` 12 s later |
| A prompt typed into a running Claude at 3% of a processor, or with paste and enter in one write | goes through: only a program that is still starting drops the enter |
| `agent_session` in `agent get` | only with herdr's own integration for that agent installed; without it a restarted agent starts fresh |
| Workspace and pane ids across a server restart | survive; `terminal_id` does not; agents are gone without an integration |
| Which event fires when an agent exits to its shell | `pane.agent_detected` (released) and a status change to `unknown` |
| A process spawned detached from a hook | survives the hook's exit; a 150-second hook was not cut off |
| `PATH` in hook-spawned processes | herdr's server environment, which can lack `~/.local/bin`: the plugin asks a login shell |
| `worktree create --cwd <repo>` with no workspace open for it | works; herdr also opens the repo itself as a workspace, which stays when the worktree is removed (so the plugin closes it) |
| Claude and Codex in a brand-new worktree with full access | both show a trust dialog, once per repository; pre-trusting removes it |
| Codex after a reply | reported `done` here; the closing note also covers `unknown` |
| `herdr machine list --json` exposing SSH targets | not verifiable here (no saved machines; it prints `[]`): name machines in the `machines` setting if `auto` finds none |
